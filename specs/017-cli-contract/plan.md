## Phase 1 — Design and Contracts

### CLI Verb Contract

See `contracts/cli-verbs.md`. Canonical enumeration of all 11 verbs, their
arguments, and their category (runner / human/ops). This is the machine-readable
source for SC-001 and SC-002 test assertions.

### Data Model

No new entities. No schema changes. Not applicable.

### Implementation Slices

Four slices, executed in order. Each slice: write test RED → verify RED → confirm
implementation makes it GREEN → run full suite (no regressions).

#### Slice A — Baseline

**Goal**: 47 prior tests green; test file compiles; no orphaned imports.

**Gate**: `pytest test_flow.py` exits 0 with exactly 47 passed.

#### Slice B — SC-001: runner verb isolation tests

**Goal**: Each of the 8 runner verbs (`add`, `next`, `context`, `note`, `done`,
`escalate`, `split`, `decide`) has at least one test that exercises its contract
in isolation, asserting the verb's documented precondition → effect.

**Approach**: `test_cli_exposes_only_contract_verbs` guards the surface; existing
tests exercise behavior. Add `test_runner_verb_contracts` — one parameterized or
grouped test that asserts each verb's core contract (e.g., `flow next` on empty DB
returns "none"; `flow note` appends to baton; `flow decide` records decision).

**TDD**: write assertions for each verb, confirm at least one is RED (the specific
assertion wording is new), then verify all pass.

#### Slice C — SC-002: human/ops verbs absent from runner loop

**Goal**: A test asserts that `reply`, `reopen`, and `list` do not appear as `flow
<verb>` CLI commands in `core.md`.

**Test name**: `test_human_ops_verbs_absent_from_runner_loop`

**Mechanism**: read `core.md`; assert `"flow reply"`, `"flow reopen"`, `"flow list"`
are not substrings; assert the 8 runner verbs ARE referenced.

**TDD**: write assertion → confirm RED (check that wording is new, i.e., the exact
assertion string doesn't exist in test_flow.py yet) → passes because core.md
correctly omits the human/ops verbs.

#### Slice D — SC-003: HLD-009 VERIFY invariant cited by ID

**Goal**: At least one test cites "HLD-009" and the full VERIFY invariant text
("runners use only the listed verbs; no direct database access; reply, reopen, and
list are human/ops-facing and not part of the runner loop") by ID.

**Test name**: `test_hld009_verify_invariant`

**Mechanism**: The test body contains the VERIFY text as a string assertion —
specifically, it checks that `core.md` does not reference the DB directly (no
`sqlite3` or `.db` imports/paths) and that the 8 runner verbs are the only `flow`
commands referenced. The function docstring or comment cites "HLD-009 VERIFY"
explicitly.

**TDD**: write the test → confirm RED (new test, specific assertions not yet in
suite) → passes against the real core.md.
